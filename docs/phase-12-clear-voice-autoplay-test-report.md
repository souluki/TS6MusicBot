# 阶段 12：清空队列后内置语音与歌单自动播放修复测试报告

## 1. 现象

执行 `clear` 后：

- 播放内置语音可能没有声音；
- 重新加入歌单后只提示“已加入”，不会自动播放；
- 手动输入 `播放` 后才开始播放。

## 2. 根因

Voice 服务的播放任务结束后，没有把共享状态恢复为 `STATE_IDLE`，仍然保留为 `STATE_PLAYING`。

后端加入歌单后的自动播放逻辑会先查询 Voice 状态，只有状态为 `STATE_IDLE` 才调用下一首播放。因此内置语音播放结束后，后端误以为仍有播放任务，自动播放被跳过。

本次排查日志已确认：

```text
clear
已清空播放队列（144 首）
!你好
正在播放内置语音：你好
歌单id 12276348850
已从歌单《某人歌单》加入 145 首歌曲
```

其中加入歌单反馈没有“已开始播放”，之后手动输入 `播放` 才启动第一首。

## 3. 修复内容

- Voice 播放任务正常结束时，将当前状态恢复为 `STATE_IDLE`。
- Voice 播放任务异常结束时，也恢复为空闲状态。
- 只有当结束任务仍对应当前播放源时才清理状态，避免旧任务覆盖新任务状态。
- 未修改 `clear` 的删除队列逻辑，未修改内置语音的混音参数。

## 4. 额外检查

当前状态接口曾显示：

```text
volume_percent = 10
```

音量为 10% 时，内置语音可能非常小。若播放反馈正常但听不到声音，先在 TS 文字频道执行：

```text
音量 100
```

然后重新测试内置语音。

## 6. 手工测试步骤

1. 重新构建并启动 Voice 服务。
2. 重启后端，使后端连接到新 Voice 服务。
3. 确认 TS Bot 已进入目标频道。
4. 设置音量：

   ```text

   ```

5. 播放内置语音指令，例如：

   ```text

   ```

6. 等待语音播放结束。
7. 执行：

   ```text
   歌单ID 12276348850
   ```
