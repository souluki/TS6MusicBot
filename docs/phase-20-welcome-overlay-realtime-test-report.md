# Phase 20：欢迎语音叠加播放完整性测试报告

## 1. 问题现象

音乐播放过程中有新用户进入时，5 秒欢迎语音有时只听到后 2 秒左右，前面的内容丢失。

## 2. 根因

欢迎语音使用 Voice 的 overlay 通道。原逻辑启动 FFmpeg 后没有限制读取速度，FFmpeg 会以高于实时的速度快速解码本地音频。

overlay 队列最多保存 50 帧，约 1 秒；队列满后会丢弃最早的帧。结果是语音前半段被丢掉，播放时只剩后半段。

## 3. 修复内容

在 `voice-service/src/main.rs` 的 overlay FFmpeg 命令中加入 `-re`，让音频按实时速度读取。这样生产速度与 TS 发送/混音消费速度一致，不会因为队列溢出丢弃语音开头。

本次只修改欢迎语音/内置语音的 overlay 读取方式，不改变普通音乐播放、音量配置或 TS 连接逻辑。

## 5. 手工复现与验收

1. 使用新构建的 Voice 启动服务。
2. 播放一首音乐。
3. 让新用户进入 Bot 所在频道。
4. 确认欢迎语音从第一个字/第一个音节开始播放，并完整播放到结尾。
5. 重复进入测试 3 次，确认每次均没有只播放尾部的情况。
